## 2026-09-09
* **Foveated SR through Cheeky, measured free**: With Cheeky's gaze-driven DLSS foveation active and NR off, the port holds 90 fps at `perDisplay 1.00`, `LATE 0`, per-cycle work ~0.9 ms -- against ~50 fps locked to 45 Hz for our NR foveation alone. The technique is not "DLAA centre, nothing outside": it is DLAA at two scales, 1:1 in the fovea (optionally supersampled via `CenterSupersampling`) and `PeripheralDlaaScale` in the periphery, both reconstructing from the same single engine render. Only an addon owning its own DLSS feature can set `PerfQualityValue`/`DLSS.Hint.Render.Preset.*` per region; the port rewrites the game's subrects in place and cannot. Cheeky hooks Streamline rather than raw NGX because Cyberpunk proxies DLSS through `sl.interposer.dll`. Recorded with the full file/key/setting list, the F12 hotkey choice verified across all four input layers, and the `PeripheralDlaaScale`-below-1-at-startup sparkle bug with its motion-vector-conversion evidence. See [foveated super resolution via CheekyFoveatedDLSS](architecture/cheeky-foveated-sr.md).
* **Cheeky's gaze bridge, and why it is not ours**: CheekyFoveatedDLSS reads gaze through its own OpenXR API layer, not through the port. Its layer was registered under `ApiLayers\Explicit` but never enabled: `reg add` writes `XR_ENABLE_API_LAYERS` without broadcasting `WM_SETTINGCHANGE`, so nothing Steam launched saw it, and the layer never loaded. Enumerated is not enabled -- a probe listing it as "visible to the loader" proved only that it was available. The port now sets `XR_ENABLE_API_LAYERS` in its own process before `xrCreateInstance` (`xr_enable_api_layers` in vrport.ini), which cannot be defeated by propagation. Verified by `HOOKDBG DLL LOAD ... CheekyOpenXRLayer.dll` in Cheeky's own log. Our path was never broken and is unaffected by `CHEEKY_OPENXR_LAYER_DISABLE` -- our gaze read `flags=0xF` while that variable was set to 1. Also: our addon host cannot serve Cheeky (it needs eight events and API 20 argument shapes; the host dispatches two at API 18 and faults in D3D12Core), so Cheeky needs real ReShade. The host now calls `AddonInit`, whose absence had made a fully-loaded addon look healthy while doing nothing. Measured with Cheeky's foveated SR active and NR off: 90 fps, `perDisplay 1.00`, `LATE 0`. See [two eye-tracking paths](architecture/eye-tracking-two-paths.md).
* **Eye-tracked NR foveation**: The DLSS-NR region now follows gaze, taken directly from the OpenXR runtime with no third-party bridge. `xrprobe` proves PSVR2 via PSVR2Toolkit delivers it — SteamVR/OpenXR 2.17.8, `playstation_vr2`, `XR_EXT_eye_gaze_interaction` v2, `supportsEyeGazeInteraction TRUE`, pose `flags 0xF`. The first probe run wrongly blamed the driver: action data only exists while the session is FOCUSED, and it had stopped at VISIBLE after 60 frames; the corrected run shows 537 frames at `0x0` then tracked on every frame after focus. The gaze action lives in the hands' existing action set because `xrAttachSessionActionSets` may be called once per session. Smoothing alone caused shimmer — a creeping centre keeps crossing the 8-pixel origin snap and each step is a discontinuity in NR's temporal history — so a deadband (0.105 tangent, ~6°) holds the centre still between saccades. 35% gaze-tracked measures ~50 fps against ~45–48 at 50%, so NR coverage is no longer the binding constraint. See [eye-tracked NR foveation](architecture/eye-tracked-foveation.md).

## 2026-08-31
* **Decisive writeback finding**: Before VRCAM activation MAIN recorded the full NR codec/writeback envelope; afterward 36 sampled MAIN evaluations recorded zero addon commands while VRCAM retained the full envelope. The addon transfers exclusive active ownership to VRCAM—MAIN's result is not produced and then erased later.
* **Ordering finding**: A collision-safe outer `slEvaluateFeature` census found strict MAIN/VRCAM alternation after VRCAM activation (64-call burst, zero violations, all success); VRCAM is later in the engine pair and recorded substantially more CPU work, strongly supporting takeover of the addon's singleton inline state.

* **Reference**: Recorded the reverse-engineered DLSS5 addon knowledge — binary identity, the `[RenoDX.DLSS5]` key set mapped to NGX parameters and F10 labels, host topology, and live-versus-restart semantics.
