CyberpunkVRPort

An open-source 6-DoF VR mod for Cyberpunk 2077. It integrates OpenXR directly into the game
engine as a RED4ext plugin - there is no dxgi.dll proxy any more.

PS VR2 fork: https://github.com/satyaloka93/cyberpunk-vr-port
Upstream:    https://github.com/dariulone/cyberpunk-vr-port


============================================================================
INSTALLATION
============================================================================

Disable OpenXR Toolkit, RivaTuner, NVIDIA overlays and any other overlay.

1. Install all dependencies and start the game once before installing this mod.

2. In the game's graphics settings: set everything to Low and turn OFF the extras - Film
   Grain, Chromatic Aberration, Motion Blur, Lens Flare, Depth of Field and Frame
   Generation. Set the display mode to borderless window.

3. If you used an earlier build of this mod, DELETE bin\x64\dxgi.dll. It is no longer part
   of the mod, and leaving it in place means two copies of every engine hook fighting over
   the same addresses.

4. Download the latest release archive and extract it into your Cyberpunk 2077 game folder,
   so the files land in:

     red4ext\plugins\CyberpunkVR_Stereo\      the VR plugin: OpenXR, stereo, overlay,
                                              sight shaders, settings
     red4ext\plugins\CyberpunkVR_Hands\       avatar, hands, weapon aim, smoking poses
     bin\x64\openvr_api.dll                   for the SteamVR (OpenVR) runtime path
     bin\x64\CyberpunkVR_SmokeGrip_right.ini  smoking / lighter hand poses
     bin\x64\CyberpunkVR_SmokeGrip_Left.ini
     bin\x64\CyberpunkVR_LighterGrip_Left.ini
     bin\x64\plugins\cyber_engine_tweaks\mods\   CET mods: Stereo, HUD, Holster, VRIK,
                                              Weapon, WorldMap, Smoking, Crosshair
     r6\scripts\                              redscript: HUD, Holster, Melee, NoAnims,
                                              WeaponUp, WorldMap, Smoking
     r6\tweaks\vrcigarette\                   TweakXL entries for the smoking props
     archive\pc\mod\                          the packed assets (the VR camera components)
     engine\config\platform\pc\               CPU tweaks tuned for two views

   Keep exactly ONE .dll in each of the two red4ext\plugins\CyberpunkVR_ folders. RED4ext
   loads every DLL it finds there, so a renamed backup beside the real build loads as a
   second copy of the plugin and the two fight over the same hooks.

5. Start your OpenXR runtime first.

6. Run Cyberpunk2077.exe, pick the render resolution and runtime in the launcher, then
   launch the game.

7. F10 - toggle the VR menu / settings.   F7 - recenter VR.

Calibration: stand in a T-pose.

============================================================================
CONTROLS
============================================================================

VR controller input is merged into the native gamepad, so the game's own Controller
bindings apply.

  Left stick fully forward      sprint (partial = jog)
  Right stick X                 turn (snap or smooth)
  Right stick fully down        crouch
  Triggers                      fire / aim
  A / B                         jump / dodge
  X / Y                         reload, interact / weapon switch
  Right grip + reach to
  shoulder or hip               equip / unequip a weapon (hand-to-holster)
  Swing a melee weapon          native VR melee along the blade
  PSVR2 Triangle touch + R3     tap = Start/system-pause; hold 0.5 s = Back/in-game menu
                                fallback; a bare R3 stays crouch
  PSVR2 left Create             manually bind in SteamVR to app SystemButton:
                                tap = Start/system-pause; hold 0.5 s = Back/in-game menu
  SteamVR dashboard             runtime-reserved; not an application action

  D-pad shifting                touch the LEFT thumbrest, then pick the direction with the
                                RIGHT stick. On PSVR2 through SteamVR, Triangle capacitive
                                touch is the modifier (UEVR LEFT_TOUCH behavior). The right
                                stick is taken out of the camera while shifting. L3 remains
                                a fallback modifier; release it without choosing and it
                                emits the normal sprint click instead.

Driving is untouched.


============================================================================
CURRENT STATE
============================================================================

Stereo

  Real stereo, not reprojection. The second eye is an actual engine view - a
  render-to-texture camera on the player entity that runs the frame graph for its own eye,
  from its own position, with its own projection. The old optical-flow reprojection (AER)
  is gone entirely, and so are its artefacts and its CUDA dependency.

  It falls back to mono automatically whenever the second view has nothing fresh to give -
  menus, loading screens, or the component being off - so those never show one live eye
  next to one frozen one.

  Mono is still the baseline and is smooth: the submitted pose is bound to the exact render
  camera the engine used for that frame.

Full-body VR avatar

  Full-body VRIK placed under the HMD, arm-length calibration, leg IK, and a real squat -
  the avatar lowers when you physically crouch.

  Motion-controlled hands with a complete shoulder -> elbow -> hand IK chain. The forearm
  does not stretch; wrist orientation, elbow bend and swivel follow the controller.

  It runs as a RED4ext plugin that writes the resolved bone rotations every frame;
  controller poses reach it through shared memory.

  Weapon tracking works.


============================================================================
FEATURES
============================================================================

  - Direct OpenXR integration inside the REDengine render path, as a RED4ext plugin.

  - Real second engine view for the second eye, with automatic mono fallback.

  - The game HUD in BOTH eyes - the engine's own HUD composite is ported shader for shader
    for the second eye and placed at a finite distance, so icons fuse instead of doubling.

  - Correct projection. The frustum we submit matches the one the engine actually rendered
    on both axes, and the resolution list follows the headset's field of view rather than
    its panel aspect. This is what fixes the "world looks too big" stretch.

  - Head tracking with in-engine camera injection, world-scale and IPD controls.

  - Decoupled VR weapon aim - bullets follow the real weapon muzzle, not the camera.
    Optional barrel dot, drawn in both eyes, zoom aware.

  - Collimated reflex sights - the reticle is placed by angle along the sight's own optical
    axis, so the dot stays on the bore instead of sliding across the glass when you look at
    the sight from the side.

  - VR motion melee - real swings trigger the game's native melee along the blade, with
    native damage, reaction and stamina.

  - Hand-to-holster equip / unequip on a grip squeeze: immersive (by visual holster) or
    simple (fixed weapon slots).

  - VR smoking - cigarette and lighter as real props, with a captured finger grip, a
    hands-free mouth anchor, and the game's own effects and audio.

  - VR controller mapping merged into XInput: full-forward sprint, full-down crouch, snap
    or smooth turn, HMD or hand relative locomotion, D-pad chord.

  - VR HUD with per-element placement and scale, world-map head-lock, CAS sharpening, and
    DLSS / NGX handling - the second view gets its own upscaler viewport automatically.

  - In-headset F10 overlay, live and persisted, with five tabs:
      General    world scale, IPD, stereo separation, VR menu FOV and quad size,
                 motion prediction, head offset
      Controls   weapon aim and its laser dot, locomotion source, snap turn and angle,
                 immersive holsters
      Stereo     which eye the second view goes to, how stale its last frame may get before
                 falling back to mono, the HUD composite, and live counters for whether the
                 second view is rendering, being captured and reaching the headset
      VRIK       start / stop tracking, IK calibration, diagnostics
      HUD        per-element X / Y / scale

  - SteamVR (OpenVR) runtime selectable alongside OpenXR. On canted headsets (Pimax, Index)
    prefer the headset's own OpenXR runtime - PimaxXR is clean, SteamVR is not, and the fix
    for that is still to come.

  - Pre-launch render-resolution selector, with per-headset presets.

  - Runtime and hardware diagnostics in the log: OpenXR runtime and system, GPU and driver,
    swapchain init, frame-pipeline events.

  - Quiet logs by default. One DEBUG tick-box in the launcher arms every diagnostic at once
    when you actually need it - expect a large log and a heavy frame time with it on.


============================================================================
KNOWN ISSUES
============================================================================

  - Magnifying scopes (Split Focus OptiX) do not converge: the reticle is drawn outside the
    optic, so the target is magnified and the dot is not. Reflex sights are correct.

  - On canted headsets use the vendor's OpenXR runtime rather than SteamVR.

  - Closing a menu costs the second eye's HUD a single-frame blip.


============================================================================
IF IT CRASHES
============================================================================

Crashing may be caused by aggressive injections. Try running it several times.

If it persists, open an issue and attach:
  bin\x64\cyberpunkvrport.log            the plugin's own log - start here
  red4ext\logs\                          script and plugin load errors
  the REDengine crash report             %LOCALAPPDATA%\REDEngine\ReportQueue\

If redscript compilation fails, EVERY redscript mod is off, not just the one that failed -
so check red4ext\logs\ first when several things stop working at once.

This is an open-source project. Please consult the relevant resources if you do not know
what that means. An incomplete fix request will not be reviewed.
